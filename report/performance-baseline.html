Baseline Summary

The current measurements support five primary conclusions.

Primary backend bottleneck Conversation summary loading scales through per-conversation hydration. The temporary-database test grows from an estimated 41 SQL queries at 10 conversations to 1,001 queries at 250 conversations.
Primary frontend bottleneck The navigation and pager configuration keeps more UI mounted than necessary. Six event lists are mounted across Home and My Events before counting Messages, Chat Thread, Join Requests, or other screens.
Measured interaction bottleneck On the connected 120 Hz Android device, representative animations have 11-13 ms median frame times and 17-31 ms p95 frame times. This exceeds the 8.33 ms frame budget needed to sustain 120 Hz and produces 60.8-88.6% legacy jank in the tested interaction windows.
Primary delivery risk TypeScript validation and the Jest suite are not green. This makes performance refactors harder to validate and slows safe iteration.
Measurement interpretation Local API timings are intentionally low because the server and SQLite database run on the same Apple Silicon machine. The scale curves and query counts are more important than the absolute local milliseconds.

Pinpointed Issues

Ranked using the measured evidence and expected user impact.

1. Conversation hydration and refresh amplification

Highest confidence

The endpoint reaches an estimated 1,001 SQL queries for 250 conversations, while the frontend contains 14 conversation-refresh callsites. Fixing only one side leaves substantial wasted work.

2. Interaction animations miss the 120 Hz frame budget

Measured on device

Bottom-tab, segment, and Create Event transitions have 11-13 ms median frame times on an 8.33 ms display budget. Discover segment switching is the strongest measured hotspot at 31 ms p95 and 84.1% legacy jank.

3. Hidden-screen and hidden-list rendering

Highest frontend priority

Native screens are disabled, all tabs are eager and attached, and the two main pagers mount six event lists. Broad context updates therefore have a larger render audience than necessary.

4. Broad context update reach

High priority

Chat and Events contexts reach 9 and 8 consumer modules respectively. Their combined values include both frequently changing data and stable actions.

5. Missing list tuning and non-virtualized details collections

Profile next

No explicit virtualization tuning props were found, while Event Details renders growing request/member collections with .map() inside a ScrollView.

6. Interaction and motion fragmentation

Consistency priority

The codebase contains 82 Pressables, 26 ScalePressables, 13 TouchableOpacity instances, 120 direct haptic calls, two animation engines, and 41 local timing declarations.

7. Web font export overhead

Quick investigation

Eighteen Inter files consume 6.0 MB of an 11 MB web export even though the app explicitly loads four weights.

8. Broken validation baseline

Roadmap blocker

TypeScript fails and Jest has 28 failures. This must be repaired before high-blast-radius performance work.

Roadmap Gates and Targets

Each phase has a measurable exit condition. Re-run this baseline after every phase.

0

Restore validation confidence

  • npx tsc --noEmit passes.
  • Jest reaches 0 failed suites and 0 failed tests.
  • Backend tests remain green.
1

Reduce mounted UI work

  • Inactive tabs are detached or frozen unless explicitly required.
  • Home and My Events mount at most the active page plus one adjacent page.
  • React Profiler confirms hidden pager pages do not rerender during active-page refreshes.
  • On the same 120 Hz device, bottom-tab and segment interactions reach at most 8.33 ms median and below 16.7 ms p95.
2

Reduce state update reach

  • A new active-chat message does not rerender Home, My Events, or Profile.
  • Event refresh does not rerender unrelated chat-thread content.
  • Context consumer render counts are recorded before and after the split.
3

Fix backend and refresh amplification

  • Conversation SQL query count becomes constant or near-constant instead of 1 + 4N to 1 + 6N.
  • At 250 conversations, local p95 is below 15 ms on the same machine.
  • Duplicate in-flight conversation refreshes are deduplicated.
  • Five-second host polling is removed or used only as a fallback.
4

Standardize interaction primitives

  • One documented sheet transition system handles the main variants.
  • Primary, secondary, icon, row, and selection controls use shared primitives.
  • Direct haptic calls fall substantially and semantic haptic APIs are used.
  • Motion timings are selected from shared tokens.
5

Control collection and bundle growth

  • Events and conversations use pagination or bounded fetching.
  • Event Details uses virtualized growing collections.
  • Web export no longer includes unused Inter font weights.
  • Bundle and asset sizes are compared against this report.

Limitations and Next Measurements

This baseline measures repository structure, build health, bundle output, backend tests, local endpoint latency, payload growth, backend scale behavior, and connected Android development-build frame behavior. It does not claim to measure production-release startup, memory, or production network latency.

  • Localhost API timings exclude mobile radio, TLS, production load, and remote database effects.
  • The temporary synthetic datasets are intentionally simple and isolate scaling behavior.
  • The connected Android package is debuggable and includes Expo Dev Launcher / Metro overhead.
  • A force-stopped development build opens Dev Launcher instead of app content, so production cold start remains unmeasured.
  • Release-build memory and React render counts remain unmeasured.
  • iOS and Android should be measured separately because keyboard, modal, navigation, and blur behavior differs.
