Issue #129 · Implementation report · 25 August 2026

Responsive Android layouts and predictable Event Details gestures

The shared inset rules now distinguish keyboard obstruction, system safe area, and app tab-bar obstruction. This removes phone-specific spacing behavior and gives Event Details explicit ownership of horizontal paging.

Implemented and verified

What changed

One keyboard-obstruction calculation

getKeyboardTranslation derives the effective overlap from the keyboard's viewport-top coordinate where available, falls back safely to height, subtracts the covered bottom inset once, and clamps the result. Bottom sheets and chat now share this rule.

Create and Profile clear bottom chrome

The Create footer includes the measured safe-area bottom. Profile scroll content includes the measured bottom-tab-bar obstruction, so destructive actions remain fully reachable above both app and system navigation bars.

Event Details owns horizontal paging

Requests and Members use a direction-locked horizontal pan with thresholds, velocity handling, edge clamping, and snap animation. Vertical movement fails the pager early and remains available to the outer details scroll view.

Route back-swipe conflict removed

Stack back-swipe is disabled only for Event Details. The visible back button and Android hardware back remain intact, while horizontal movement inside the tab area cannot unexpectedly pop the route.

Fixed UI evidence

Device evidence: Android emulator at 1080×2400 / 420 dpi with three-button navigation; Samsung SM-A566E at 1080×2340 / 450 dpi. The reporter confirmed the keyboard, chat, Profile, Create, scrolling, and paging issues are fixed on the physical phone.
