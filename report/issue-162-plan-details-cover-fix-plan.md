# Issue 162: Plan Details cover reproduction and fix plan

Investigated October 4, 2026. Source: [plan details #162](https://github.com/antash-mishra/who-else-is-free/issues/162). Reviewed the issue and its comment. This is an investigation and implementation plan; no production fix has been made.

The requested outcome is a level cover that appears at its final size without a cover transition, scrolls with the page without parallax, and has no Android shadow. Tilt and Android shadow were already visible to the requester; they did not need separate reproduction.

## Fix plan

1. **Specify the static hero contract with focused failing tests.** Expand `src/screens/event-details/__tests__/EventDetailsHero.test.tsx` to assert first mount and remount both render the cover immediately at full opacity, without scale/rotation/translation. Verify both images explicitly disable their image transition. Exercise normal and reduced-motion settings, different URIs, and nonzero top insets. Add a scroll regression that executes the existing worklet with a nonzero offset and demonstrates today's cover/backdrop translations before removing that coupling. Keep the current valid rendering tests. Freeze animation progress when necessary so Reanimated's instant-completion mock cannot conceal initial styles.
2. **Make only the Plan Details hero static.** In `EventDetailsHero.tsx`, replace its `Placed` wrapper with an ordinary `View`, preserving `hero-cover-card` and existing square geometry. This removes entry scale, fade, rise, and resting tilt together. Setting only `tiltMode="none"` would still scale/fade/rise. Leave the shared `Placed` primitive and its use on event-list rows and going avatars intact. Render the blurred backdrop with ordinary `Image` and the cover container with ordinary `View`; remove the two animated styles, rates, and `scrollY` prop. Set `transition={0}` on foreground and backdrop images to honor the requested absence of a cover transition. Preserve blur, overlays, crop mode, radii, dimensions, and safe-area spacing.
3. **Remove obsolete scroll wiring from both screen paths.** `EventDetailsScreen.tsx` creates `scrollY` solely for the hero. Remove that shared value, handler, hero argument, and their listeners. Use a normal `ScrollView` on the main details path. In `ReadOnlyEventDetails.tsx`, remove the now-unused `onScroll` prop/listener and use a normal `FlatList`; retain virtualized members, list header, and `bounces={false}`. Update nearby screen/list tests and fixtures to match this internal prop removal. Keep the standard route slide, navigation, pinned buttons/CTA, member lists, host actions, and scrolling behavior.
4. **Remove the Android image shadow locally.** In `EventDetailsScreen.styles.ts`, remove hero `elevation: 15`. Put its legacy shadow properties behind an iOS-only platform style so Android receives no hero shadow properties, elevation, or replacement `boxShadow`. Keep the existing iOS shadow because the issue names Android specifically. Add style assertions under Android and iOS platform mocks. The `imageCard` style is used only by this hero; no global shadow-token change is needed.
5. **Update the documented contract in the implementation change.** `AGENTS.md`, `CLAUDE.md`, and `report/shared-components-refactor-guide.md` currently describe hero `Placed` entry / parallax as intentional. The explicit requirement in #162 supersedes that convention. Replace those hero-specific statements with the static-cover contract and remove the hero from the `Placed` usage list; retain the motion rules for its other users. Keep QA history in `TEST_RUNS.md` and this report.
6. **Validate the completed fix.** Run focused hero, `Placed`, read-only details, and screen-rendering tests; then frontend suite, typecheck, lint, touched-file Prettier checks, and `git diff --check`. Manually verify ordinary and past-plan/read-only details, first/repeated opening, two plans sharing a URI, different catalog and uploaded covers, scrolling down/up, reduced motion, and back navigation. Confirm on Android and iOS that the cover is level, stays at final size once present, and tracks the content without drift. Verify Android has no shadow and iOS retains its existing shadow. Check Discover/My Plans row entry and going-avatar animations remain unchanged. Before declaring the visual issue fixed, inspect a physical Android phone too.
