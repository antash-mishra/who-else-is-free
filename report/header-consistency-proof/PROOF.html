Connection state no longer hijacks the subtitle

Before: a reconnecting WebSocket replaced the entire subtitle with a bare Connecting… line, hiding the member/date info.
After: the member/date subtitle stays visible at all times, and a subtle pulsing-dot ConnectionStatusIndicator ("● Connecting") appears in the header's right area only while isConnecting is true, then disappears.

Covered by unit tests in ChatThreadScreen.rendering.test.tsx: "should keep the member/date subtitle visible while connecting" and "should show the connection status indicator when isConnecting is true".

Code changes

  • src/utils/chatHeaderSubtitle.ts (new) — shared buildEventMemberSubtitle & buildOneToOneSubtitle helpers.
  • src/components/ConnectionStatusIndicator.tsx (new) — pulsing-dot pill for the connecting state.
  • src/screens/JoinRequestsScreen.tsx — 1:1 + group headers use the shared subtitle helper; removed the old time/location subtitle memo.
  • src/screens/ChatThreadScreen.tsx — 1:1 + group subtitles use the shared helpers; connection state moved from subtitle into ConnectionStatusIndicator.
  • Tests: src/utils/__tests__/chatHeaderSubtitle.test.ts (new) + updated assertions in JoinRequestsScreen.rendering.test.tsx & ChatThreadScreen.rendering.test.tsx.
