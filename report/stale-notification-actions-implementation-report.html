Added migration/lifecycle/routing/UX coverage, content-free resolver logging, public API regression checks, and sequential Group plus 1:1 Android verification.

Product decisions applied

  • Resolved requests with a surviving event open Event Details.
  • Past pending requests follow the existing lifecycle; no new automatic expiry policy was invented.
  • The current server-owned denied copy stays unchanged and remains separate from action validity.
  • Inactive task groups remain as one muted historical summary; outcomes remain until clear-all/account deletion.
  • Resolver logs include user ID, status, reason, destination, and ID count—but never notification content.

Rollout notes

  • The startup migration is idempotent and runs before action indexes/backfill queries.
  • Push persistence remains best-effort: insert failure never blocks FCM delivery.
  • Legacy/no-ID pushes are intentionally supported permanently and always revalidate current access.
  • Aggregate the notification action resolved log by reason to watch unavailable rates and find missed invalidation paths.
