Shared CSS In React Native

This repo does not use browser CSS for React Native screens. Shared CSS means shared theme tokens plus shared components that own visual states, motion, haptics, accessibility, and disabled/loading behavior.

Token Files

  • src/theme/colors.ts
  • src/theme/components.ts
  • src/theme/layout.ts
  • src/theme/radii.ts
  • src/theme/shadows.ts
  • src/theme/spacing.ts
  • src/theme/typography.ts
  • src/theme/springs.ts

Rule Of Thumb

If a value or interaction appears in multiple places, prefer a token or shared primitive before adding another local style object.

New Shared UI Primitives

AppButton

src/components/ui/AppButton.tsx

Use for primary, secondary, destructive, and ghost CTA buttons. It owns loading, disabled state, haptics, accessibility state, button text styling, and variants.

  • Before: local Pressable or TouchableOpacity button styles.
  • Now: one shared button backed by theme component tokens.
  • Used by EmptyState, SignInButtons, and HelpForm.

AppTabs

src/components/ui/AppTabs.tsx

Use for repeated pill or underline tabs. SegmentedControl is now a thin wrapper around this component.

  • Before: each tab surface could carry separate selected styling and motion.
  • Now: count labels, selected state, tests, and haptics are centralized.
  • Used by Discover Events and My Events through SegmentedControl.

AppText

src/components/ui/AppText.tsx

Use for common text variants such as title, subtitle, body, caption, button, and error text.

  • Before: repeated font families, sizes, line heights, and muted/error colors.
  • Now: typography variants live in one small primitive.
  • Used by empty states and help screens.

TextField

src/components/ui/TextField.tsx

Use for common single-line and multiline text inputs with consistent surfaces, padding, placeholder color, and error text.

  • Before: forms repeated input backgrounds, radius, padding, and errors.
  • Now: the input surface has one owner.
  • Used by HelpForm.

CheckboxRow

src/components/ui/CheckboxRow.tsx

Use for checkbox-style rows that need consistent row layout, selected state, accessibility role, disabled behavior, and selection haptics.

  • Before: help form checkbox visuals were local.
  • Now: checkbox rows share one primitive.
  • Used by HelpForm.

IconButton

src/components/ui/IconButton.tsx

Use for close, back, header, and small icon-only actions. It wraps ScalePressable with standard sizes, hit slop, variants, haptics, and labels.

  • Before: close/header icons repeated sizing and hit slop.
  • Now: icon-only actions share one implementation.
  • Used by ScreenHeader and SheetHeader.

ListSeparator

src/components/ui/ListSeparator.tsx

Use for simple list dividers so color, inset, and hairline width are tokenized.

SectionHeaderText

src/components/ui/SectionHeaderText.tsx

Use for repeated section labels in settings, lists, and help surfaces.

Shared Press And Haptics

ScalePressable

src/components/ScalePressable.tsx

ScalePressable still owns press-scale animation, and now also accepts a semantic haptic prop. Shared components can feel the same without each screen wiring feedback by hand.

triggerHaptic

src/services/haptics.ts

Direct expo-haptics imports are centralized in one service. Callers use semantic names such as selection, light, submit, success, warning, error, and destructive. 

<ScalePressable haptic="light" onPress={openMenu}>
  <Text>Open menu</Text>
</ScalePressable>

Shared Sheet And Overlay Foundations

BottomSheet

src/components/sheets/BottomSheet.tsx

Owns modal vs inline presentation, keyboard avoidance, snap height, backdrop, open/close animation, max height, safe area, and shared sheet styling.

  • Before: BottomSheetModal and CreateEventBottomSheet duplicated sheet mechanics.
  • Now: wrappers keep old APIs while delegating the foundation to BottomSheet.

SheetHeader

src/components/sheets/SheetHeader.tsx

Provides shared sheet titles and close buttons using IconButton.

SheetActionList

src/components/sheets/SheetActionList.tsx

Provides vertical sheet action rows with loading, disabled, destructive, and haptic behavior.

EventActionOverlay.prompts

src/components/EventActionOverlay.prompts.tsx

Splits prompt bodies away from EventActionOverlay, so the top-level overlay just chooses a prompt variant and renders it in BottomSheetModal.

Before And Now

Before

  • Local button implementations repeated height, radius, color, disabled state, loading, and haptics.
  • Inputs repeated placeholder colors, padding, surfaces, multiline behavior, and error text.
  • Sheets duplicated animation, backdrop, keyboard avoidance, safe-area, and close-button styling.
  • Event screens repeated section list scaffolding and event-card mapping.
  • Direct expo-haptics imports spread across screens.

Now

  • AppButton, TextField, AppTabs, and IconButton own common UI behavior.
  • BottomSheet, SheetHeader, and SheetActionList own sheet mechanics.
  • EventSectionList and section helpers own repeated event list behavior.
  • triggerHaptic centralizes semantic feedback.
  • Theme tokens are the preferred shared styling layer.
// Before: local button details in a screen
<Pressable onPress={handleSubmit} style={styles.button}>
  <Text style={styles.buttonText}>Send message</Text>
</Pressable>

// Now: shared button owns visual and interaction states
<AppButton
  label="Send message"
  onPress={handleSubmit}
  loading={isSubmitting}
  disabled={isSubmitting}
  haptic="submit"
/>

What To Use For New Work

Need Use
Primary, secondary, destructive, or ghost CTA AppButton
Icon-only close, back, or action button IconButton
Common press scale or haptic wrapper ScalePressable
Single-line or multiline input TextField
Checkbox row CheckboxRow
Tabs or segmented controls AppTabs or SegmentedControl
Simple shared text variant AppText
Bottom sheet BottomSheetModal or CreateEventBottomSheet wrapper
Sheet action menu SheetActionList
Event card sections EventListPage and EventSectionList
Haptic feedback triggerHaptic or a shared component haptic prop
Fetch timeout createRequestTimeout

Remaining Follow-Up

  • Continue replacing screen-local one-off buttons with AppButton where the visuals match.
  • Continue replacing repeated text inputs with TextField.
  • Consider moving more Event Details tab UI to AppTabs once behavior is stable.
  • Keep direct expo-haptics imports restricted to src/services/haptics.ts.
  • Keep AGENTS.md updated when new primitives, conventions, or validation rules are added.
