Why This Exists

This refactor introduced shared React Native UI foundations so screens stop rebuilding the same buttons, tabs, bottom sheets, empty states, event lists, haptics, and request helpers in slightly different ways.

  • same-looking UI should behave the same way
  • shared interactions should own their animation and haptics
  • repeated styling should live in theme tokens or shared components
  • screens should mostly compose shared pieces instead of rebuilding them

Mobile QA Fixes From 8c92001

The first shared-component pass had a few mobile issues. They are documented in report/member-pending-requester-mobile-issues.md and fixed in 8c92001 Fix member mobile layout issues.

Issue Fix Rule Going Forward
Action sheet had too much empty space. EventActionOverlay only avoids keyboard for input prompts. BottomSheet uses explicit keyboard listeners. Non-input sheets should not avoid the keyboard. Input sheets should.
My Events empty states looked cropped. EmptyState, EventSectionList, and My Events image sizing were adjusted. Lists own empty-state placement. Empty components own content only.
Discover could look blank while location loaded. Discover no longer blocks event rendering when event data exists. Loading gates should not hide usable data.
Inactive tabs/pages were exposed to accessibility. TabAccessibilityBoundary and AnimatedPager hide inactive content from accessibility and pointer events. Hidden UI should not be reachable by screen readers or tests.
Overlay content was cramped near the bottom safe area. Event Details sheet mode now adds bottom padding when no CTA is pinned. Overlay content needs safe-area padding.
Destructive confirmation was not exposed as a button. HoldToConfirmButton now exposes role, label, disabled state. Custom pressables need accessibility role, label, and state.

Main Components

UI Primitives

AppButton, AppText, TextField, CheckboxRow, IconButton, AppTabs, ListSeparator, and SectionHeaderText.

They own common states such as pressed, disabled, loading, selected, destructive, error, accessibility, and haptics.

Sheets And Overlays

BottomSheet, SheetHeader, SheetActionList, BottomSheetModal, CreateEventBottomSheet, and EventActionOverlay.

Use keyboard avoidance only for input overlays such as invite and report prompts.

Event Lists And Empty States

EventListPage, EventSectionList, eventListSections, and EmptyState.

The list owns placement. The empty state owns content.

Navigation And Hidden Content

AppNavigator, navigation/types, pushRouting, and AnimatedPager.

Inactive tabs and pager pages should be hidden from accessibility and pointer events.

Before And Now

Before

  • buttons had different press feedback, disabled styles, and loading states
  • sheets had different keyboard and safe-area behavior
  • event lists duplicated scaffolding
  • empty states were centered differently per screen
  • haptics were imported directly from expo-haptics

Now

  • AppButton owns common CTA behavior
  • BottomSheet owns sheet mechanics
  • EventSectionList owns event-list rendering
  • EmptyState owns content while list wrappers own placement
  • triggerHaptic owns semantic haptics
<AppButton
  label="Send message"
  onPress={handleSubmit}
  loading={isSubmitting}
  disabled={isSubmitting}
  haptic="submit"
/>

Remaining Follow-Up

  • Continue migrating matching one-off CTAs to AppButton.
  • Continue migrating repeated inputs to TextField.
  • Keep non-input sheets from using keyboard avoidance.
  • Keep inactive tabs and pager pages hidden from accessibility.
  • Keep direct expo-haptics imports restricted to src/services/haptics.ts.
  • Keep AGENTS.md updated when new primitives or validation rules are added.
