Purpose

This document explains what each shared component is responsible for, where it is currently used, and which styling files act as the app's shared CSS layer.

In this React Native app, shared CSS means shared theme tokens in src/theme, shared component styles owned by reusable components, and feature-level .styles.ts files for complex components.

Shared Styling

src/theme/colors.ts

Named palette and semantic colors for app surfaces, text, inputs, buttons, navigation, event details, create event, and overlays.

Used by: almost all screens, UI primitives, sheets, navigation, event cards, help, profile, chat, create event, and modals.

src/theme/spacing.ts

Shared spacing scale: xs, sm, md, lg, xl, xxl.

Used by: screen headers, lists, sheets, help forms, profile, messages, create event, and modal styles.

src/theme/typography.ts

Font families, sizes, line heights, and letter spacing.

Used by: AppText, AppButton, EventCard, sheet headers, Help, Profile, Messages, Event Details, and Create Event.

src/theme/components.ts

Component dimensions for buttons, inputs, checkbox, icon buttons, avatars, overlays, segmented controls, and event lists.

Used by: UI primitives, sheets, event lists, and hold-to-confirm controls.

src/theme/radii.ts

Shared radius scale including pill and sheet.

Used by: buttons, icon buttons, sheet actions, bottom sheets, tabs, and modal surfaces.

src/theme/shadows.ts

Shadow presets for card, floating, and sheet surfaces.

Used by: BottomSheet and available for card/floating surfaces.

src/theme/layout.ts

Screen padding, header height, tab height, sheet z-index, and hit slop values.

Used by: ScreenContainer, IconButton, BottomSheet, navigation layout.

src/theme/springs.ts

Motion presets for press feedback, navigation, tabs, sheets, badges, and pager motion.

Used by: ScalePressable, AnimatedPager, AppTabs, BottomSheet, AppNavigator, CreateEventScreen.

Rules For New Work

  • Use shared components before adding local UI.
  • Add a theme token before repeating a raw color, radius, shadow, spacing value, or component size.
  • Shared components should own default, pressed, disabled, loading, selected, error, and destructive states.
  • Shared interactions should own motion, haptics, accessibility role/state, and hit slop.
  • Keep screen components focused on orchestration and composition.
  • Keep feature-specific style files next to their component until a pattern becomes broadly shared.
  • Keep AGENTS.md updated when adding a new shared primitive, token file, helper, or validation rule.
